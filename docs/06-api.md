# 06 — HTTP API

Step 6 puts a FastAPI app in front of the registry. Code: `src/gateway/app.py`, plus
`MetricsRecorder` in `metrics.py` and `aclose` on the workers and registry.
Tests: `tests/test_app.py`.

**Updated by the metrics step (`docs/05-metrics.md`, built after step 13).** `MetricsStore`
replaced `MetricsRecorder`. `/metrics/summary` keeps the shape shown below; its percentiles
now cover the last five minutes (at most 10,000 requests per model) instead of every
request since the process started, and `GET /metrics/detail` has the fuller figures.

**Updated by settings PR S1 (`docs/39-settings.md`).** Every answer also carries
`X-Max-Tokens-Applied`: the `max_tokens` the request was served with (its own, or its
application's `default_max_tokens`), or `none` when no limit applies.

**Updated by platform step 2 (`docs/20-applications-api-keys.md`).** Tenants are now applications, and a request names its application with an API key (`Authorization: Bearer <key>`), not a `tenant_id` in the body, which is now a 422. Usage moved to `GET /v1/applications/me/usage`. The examples below predate that.

**Updated by the routing step (`docs/09-routing.md`).** The default server now loads tenant
plans, so every `/v1/generate` call to it needs a `tenant_id` (`initech`, `globex` or `acme`
in the packaged plans); without one it returns 401. Requests may give a `quality` in place
of a `model`, responses carry `X-Model-Used` and `X-Cost-USD` headers, and there is a
`GET /v1/tenants/{id}/usage` endpoint. The examples below were recorded with
`"tenant_id": "acme"` in the request bodies, as they now need.

## Running it

```sh
uv run uvicorn gateway.app:create_default_app --factory --port 8000
```

`create_default_app` wires `WallClock`, one `ContinuousBatchingWorker` with a prefix cache
per tier, and the `SimulatedBackend`. `GATEWAY_SEED` (default `0`) seeds the simulated
output lengths. **No model runs**: the server waits for as long as the cost model says and
returns placeholder text.

Interactive docs are at `/docs` (Swagger UI, generated by FastAPI).

## Endpoints

### POST /v1/generate

Request body:

| Field        | Type    | Required | Notes                                                   |
|--------------|---------|----------|---------------------------------------------------------|
| `model`      | string  | yes      | A model id or alias from `/v1/models`.                  |
| `prompt`     | string  | yes      | Non-empty.                                              |
| `max_tokens` | integer | no       | At least 1. Caps the output length.                     |
| `tenant_id`  | string  | no       | Non-empty if given. Accepted and validated, not yet used. |

Unknown fields are rejected.

```sh
curl -s -X POST http://127.0.0.1:8000/v1/generate \
  -H "Content-Type: application/json" \
  -d '{"model": "economy", "prompt": "You are a helpful assistant. Explain what a radix tree is.", "max_tokens": 32, "tenant_id": "acme"}'
```

```json
{
  "id": "req-1",
  "text": "[simulated output, 32 tokens]",
  "model": "economy",
  "usage": {"prompt_tokens": 11, "cached_tokens": 0, "completion_tokens": 32, "total_tokens": 43},
  "timing": {"queue_ms": 97.86110019683838, "ttft_ms": 128.12660026550293, "total_ms": 601.7565002441406},
  "cost": {"usd": 6e-6}
}
```

- `model` is the registered id the request resolved to, even if an alias was sent.
- `usage.cached_tokens` is the part of `prompt_tokens` served from the prefix cache; it is
  neither prefilled nor billed.
- `timing.queue_ms` is enqueue to start, `ttft_ms` enqueue to first token, `total_ms`
  enqueue to finish, all read from the app's clock.
- `cost.usd` uses the placeholder prices of note 01 (operator-supplied, not data), times the
  tenant plan's multiplier (note 09).
- `id` is a per-process counter (`req-1`, `req-2`, ...), not a UUID, so runs stay
  reproducible.

Sending the same prompt again, through the alias `llama-3.2-1b`, hits the cache:

```json
{
  "id": "req-2",
  "text": "[simulated output, 32 tokens]",
  "model": "economy",
  "usage": {"prompt_tokens": 11, "cached_tokens": 11, "completion_tokens": 32, "total_tokens": 43},
  "timing": {"queue_ms": 86.79789996147156, "ttft_ms": 101.48000025749207, "total_ms": 578.255900144577},
  "cost": {"usd": 5.120000000000001e-6}
}
```

## Errors

Every error body is JSON of the form `{"error": {"code", "message", ...}}`.

| Status | `code`              | When                                              | Extra fields                |
|--------|---------------------|---------------------------------------------------|-----------------------------|
| 404    | `unknown_model`     | `model` is not a registered id or alias.          | `valid_models`              |
| 422    | `invalid_request`   | Missing, empty, wrongly typed or unknown fields; malformed JSON. | `details`, `valid_models` |
| 413    | `request_too_large` | Prompt plus output cannot fit the model's KV capacity. | none                   |

```sh
curl -s -X POST http://127.0.0.1:8000/v1/generate \
  -H "Content-Type: application/json" -d '{"model": "gpt-4", "prompt": "hi", "tenant_id": "acme"}'
```

```json
{
  "error": {
    "code": "unknown_model",
    "message": "Unknown model 'gpt-4'.",
    "valid_models": ["economy", "standard", "premium", "llama-3.2-1b", "llama-3.2-3b", "llama-3.1-8b"]
  }
}
```

```sh
curl -s -X POST http://127.0.0.1:8000/v1/generate \
  -H "Content-Type: application/json" -d '{"model": "economy", "max_tokens": 0, "tenant_id": "acme"}'
```

```json
{
  "error": {
    "code": "invalid_request",
    "message": "The request is not valid.",
    "details": [
      {"field": "prompt", "message": "Field required"},
      {"field": "max_tokens", "message": "Input should be greater than or equal to 1"}
    ],
    "valid_models": ["economy", "standard", "premium", "llama-3.2-1b", "llama-3.2-3b", "llama-3.1-8b"]

}
```

## Where the example outputs came from

The responses above were copied from one local run of the server (`uvicorn` on Windows 11,
Python 3.12) on the tree of the commit that added this text (parent commit `38bbb94`), using
the curl commands shown, in this order: models, generate, generate again with the alias
`llama-3.2-1b`, the two error calls, healthz, metrics. The JSON is reformatted for reading.
The examples first recorded for this note ran on invented profiles and were replaced (note 13).

**The timings in them are not model performance.** They are wall-clock waits of a simulator
running on the calibrated profiles (note 01). They are also longer than the cost model asks
for: the first request's 32 decode steps at 6.7 ms are 215 ms after a 90 ms overhead and 2 ms
of prefill, but it took about 600 ms, because each step is a separate `asyncio.sleep` and the
operating system's timer on that machine rounds short sleeps up to roughly 15 ms (its
inter-token gaps are 15 to 16 ms). Under `WallClock` the reported timings are what really
elapsed, so they include this. Under `SimClock` they match the cost model exactly, which is
what the tests check. Costs are at placeholder prices.

## Design decisions

- **App factory.** `create_app(registry, clock)` takes an already wired registry, so tests
  build one on a `SimClock` and assert exact timings through HTTP, with no real waiting.
  `create_default_app()` is the production wiring. `app.py` is the only module that imports
  FastAPI.
- **Scheduler loops are background asyncio tasks on the server's event loop.** Each worker
  starts its loop task on the first request for its model and the task parks when the model
  is idle, as in steps 2 and 3; the app does not start idle loops at startup. On shutdown
  the app's lifespan calls `registry.aclose()`, which cancels each worker's task and every
  request it still holds. A closed worker refuses new requests.
- **Concurrent requests are batched** because they are submitted to the same worker from
  separate request handlers on one event loop. `test_concurrent_requests_to_the_same_model_
  are_batched` sends three at once and checks every decode step carried all three.
- **`text` is a placeholder**, `"[simulated output, N tokens]"`. The simulator generates
  token counts, not tokens.
- **`tenant_id` is accepted but unused.** Mapping tenants or plans to tiers is the routing
  step, which does not exist yet; today the client names the model.
- **`valid_models` is in both 404 and 422 bodies**, listing ids then aliases.
- **Metrics keep every result in memory** and compute percentiles on request. Fine for a
  simulator; a long-running server needs a bounded window or a histogram.
- **No auth, rate limiting, streaming or request timeout.** Out of scope for this step.
- **The clock argument** is used by the app itself only for `uptime_ms`; request timings
  come from the workers, which were built on the same clock.
