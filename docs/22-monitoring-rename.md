# 22 — Monitoring: tenants become applications

Step 4 of the platform plan (`docs/platform-plan.md`). Since note 20 the gateway's callers are
applications; monitoring still called them tenants. This step renames them in the snapshot,
the Prometheus output, the events and the dashboard, and adds one thing: rate-limit refusals
are a rejection reason. Nothing else changes. Note 15 has the current schema.

## The rename

| Before | After |
|---|---|
| snapshot `tenants: {available, tenants}` | `applications: {available, applications}` |
| event field `tenant_id` | `application_id` |
| Prometheus `gateway_tenant_*{tenant="…"}` | `gateway_application_*{application="…"}` |
| dashboard tab "Tenants" | "Applications" |
| Events filter "Tenant" | "Application" |
| `TenantSnapshot`, `TenantPoint`, `TenantTotals`, `tenant_*` methods | `Application…`, `application_*` |
| `TenantUsage`, `BudgetExceededError.tenant_id` (ledger) | `ApplicationUsage`, `.application_id` |

The ledger was renamed with the rest because monitoring reads its errors; its budget message
now says "Application 'x' has used …". The request body's `tenant_id`, refused with a 422
since note 20, keeps its name: that is the name a client might still send.

## The addition

`rejections_total` has a third reason, `rate_limited`: requests refused by the
application's requests-per-minute limit (note 20), counted since the gateway started, and in
the per-second `rejections` series. They never reached a model, so they appear in no model
series and raise no event; Prometheus has them as
`gateway_application_rejections_total{application="…",reason="rate_limited"}`. The
Applications tab shows them in a "Rejected: rate limit" column.
`test_requests_per_minute_limit_answers_429_with_retry_after` checks the snapshot, the
Prometheus line, and that only the served requests arrived at a model.

## What moved, and what did not

- **Fixtures** were regenerated by `tests/test_dashboard.py` (never edited): the diff is the
  renamed keys and `"rate_limited": 0` in each application's rejections, nothing else.
- **The frontend** types, store, derive functions, Playground, Applications tab (was
  `Tenants.tsx`), Events and their tests, and the e2e specs, follow the API.
- **Pictures** in `docs/img/` were retaken with `scripts/capture_demo.py` (installed Chrome,
  simulated live mode, seed 7): `tenants.png` is now `applications.png`, and every other
  picture and both GIFs were taken again. Simulated, as all of them.
- **The protected outputs** are unchanged: the no-applications path has no monitoring of
  applications at all.
- **Simulated live mode** stays deterministic: `tests/test_live_sim.py` compares every event
  and snapshot across speeds, under the new names.
